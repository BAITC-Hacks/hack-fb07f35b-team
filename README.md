# FAQ-бот для репетиции хакатона (`hack-fb07f35b-team`)

Автономный консольный ассистент на чистом Python для мгновенных и точных ответов на ключевые организационные вопросы участников репетиции хакатона.

---

## 1. Название проекта

**FAQ-бот репетиции хакатона** (команда `hack-fb07f35b-team` / BAITC-Hacks).

---

## 2. Краткое описание

### Какую проблему решает
Во время проведения хакатона организаторы и менторы сталкиваются с огромным потоком однотипных повторяющихся вопросов от участников: регламент и расписание дня, требования к составу команд, правила сдачи и формат репозитория, призовой фонд и условия финала. Это отвлекает команду организаторов от решения критических инцидентов и помощи участникам по существу задач.

### Для кого предназначен
- **Для участников хакатона**: обеспечивает мгновенный доступ к проверенным ответам без необходимости ждать реакции модераторов в общем чате или искать информацию в документах.
- **Для организаторов и менторов**: снимает 100% рутинной нагрузки первого уровня поддержки по 5 базовым направлениям репетиции.

---

## 3. Что реализовано

- **Интерактивный диалоговый режим (CLI REPL)**: удобный консольный чат с приветственным меню, списком поддерживаемых тем и корректным завершением сессии по командам `выход`, `exit` или сочетанию `Ctrl+C`.
- **Режим одиночного запроса (CLI Argument)**: возможность передать вопрос напрямую аргументом командной строки (`python bot.py "Вопрос"`), что удобно для интеграции в скрипты и быстрой проверки.
- **Интеллектуальный NLP-поиск по базе знаний**:
  - Токенизация и удаление пунктуации с помощью регулярных выражений.
  - Фильтрация русских стоп-слов (предлоги, союзы, частицы).
  - Алгоритмический морфологический стемминг для русского языка (отсечение падежных и глагольных окончаний с сохранением смысловой основы слова).
  - Двухуровневый скоринг: совпадение по корням слов вопроса + сопоставление с тематическими словарями ключевых корней.
- **Механизм отсечения неизвестных запросов (Threshold Validation)**:
  - При отсутствии совпадений или запросах не по теме (оффтоп) бот не галлюцинирует, а выдает вежливое сообщение о том, что ответ неизвестен, и подсказывает доступные темы.
  - Обработка пустых строк с подсказкой пользователю.
- **Кроссплатформенность и поддержка Windows**: принудительная настройка потоков `sys.stdin`, `sys.stdout`, `sys.stderr` на UTF-8 для корректного отображения кириллицы в консоли Windows.
- **Автоматизированное тестирование**: набор из 8 модульных тестов на базе встроенного фреймворка `unittest` (`test_bot.py`), покрывающий все 5 тематик, граничные случаи и валидацию.

## 4. Как работает решение

Основной пользовательский сценарий от входных данных до результата:

```
[Пользователь]
      │
      ▼  (Текстовый вопрос на естественном русском языке)
┌────────────────────────────────────────────────────────┐
│ 1. Инициализация и нормализация                         │
│    • Приведение к нижнему регистру                     │
│    • Токенизация: regex [a-zA-Zа-яА-ЯёЁ0-9]+           │
│    • Удаление стоп-слов из STOP_WORDS                  │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ 2. Морфологический стемминг                             │
│    • Усечение окончаний (-ами, -ого, -ить, -а, -е...)  │
│    • Получение множества корней запроса (user_stems)   │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ 3. Скоринг релевантности (по каждому пункту FAQ)       │
│    • Пересечение корней вопроса и FAQ (+2.0 за совп.)  │
│    • Совпадение с кластером ключевых слов (+3.0 за совп│
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ 4. Принятие решения (порог уверенности: 2.0)           │
│    • Score >= 2.0 ──► Возврат точного ответа из базы   │
│    • Score < 2.0  ──► Возврат fallback-сообщения       │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
[Ответ в консоль с префиксом «Бот: »]
```

### Пошаговый сценарий:
1. **Вход**: участник запускает бота и вводит вопрос в свободной форме (например: `«куда отправлять проект?»`).
2. **Очистка**: фраза разбивается на токены `['куда', 'отправлять', 'проект']`, стоп-слово `'куда'` отсекается.
3. **Стемминг**: оставшиеся слова преобразуются в корни `{'отправл', 'проект'}`.
4. **Скоринг**:
   - Вопрос №4 в FAQ: `«Как и куда сдавать готовый проект?»`.
   - Корни вопроса FAQ: `{'сдава', 'готов', 'проект'}`.
   - Пересечение корней: `'проект'` (+2.0 балла).
   - Тематические ключевые слова темы сдачи: `{'сдач', 'сдат', 'дедлайн', 'ссылк', 'гит', 'репо', 'репозитор', 'формат', 'куда', 'отправ'}`.
   - Корень `'отправ'` совпадает с ключевым словом темы (+3.0 балла).
   - Итоговый балл: **5.0** (значительно выше порога 2.0).
5. **Результат**: бот выдает точный ответ из базы:
   > *«Проект сдаётся до 17:30 в виде ссылки на публичный git-репозиторий команды с README (инструкция по запуску и описание).»*

## 6. Архитектура проекта

### Файловая структура

```text
HackAlem/
├── faq.txt          # База знаний: структурированные пары «Вопрос - Ответ»
├── bot.py           # Основной модуль: токенизация, стемминг, скоринг и CLI-интерфейс
├── test_bot.py      # Набор модульных тестов (unittest)
├── .gitignore       # Исключение временных файлов (__pycache__, артефакты тестов)
└── README.md        # Документация проекта для жюри и участников
```

### Взаимодействие компонентов

1. **`faq.txt`** хранит структурированные записи в формате:
   ```text
   Q: <Текст вопроса>
   A: <Текст ответа>
   ```
2. **`bot.py`** при запуске:
   - Считывает `faq.txt` через функцию `load_faq()`.
   - Инициализирует словарь тематических кластеров `TOPIC_KEYWORDS` (время, команда, трек, сдача, призы).
   - Запускает бесконечный цикл диалога или обрабатывает аргументы командной строки `sys.argv`.
   - Передает входящий запрос в функцию `find_answer()`, которая вызывает `calculate_match_score()`, `tokenize()` и `stem_word()`.
3. **`test_bot.py`** импортирует функции ядра из `bot.py`, проверяет целостность базы `faq.txt` и корректность ответов на эталонные запросы.

## 7. Установка и запуск

### Требования
- Установленный интерпретатор **Python 3.10** или выше.
- Дополнительные пакеты (`pip install`) **не требуются**.

### 1. Клонирование репозитория
```bash
git clone https://github.com/BAITC-Hacks/hack-fb07f35b-team.git
cd hack-fb07f35b-team
```

### 2. Запуск в интерактивном режиме (диалог)
```bash
python bot.py
```
*Для завершения диалога введите `выход` или `exit`.*

### 3. Запуск одиночного запроса через аргументы
```bash
python bot.py "Во сколько начало репетиции?"
```

### 4. Запуск автоматических тестов
```bash
python -m unittest test_bot.py
```

## 9. Данные и интеграции

- **Источник данных**: локальный файл базы знаний `faq.txt`, содержащий регламент и правила проведения репетиции хакатона:
  1. Время и расписание мероприятия.
  2. Правила формирования и состав команды.
  3. Описание направления/трека разработки.
  4. Формат и дедлайн сдачи решения.
  5. Призовой фонд и награды.
- **Внешние API и сервисы**: внешние сервисы и интеграции **не используются**. Решение полностью автономно, не требует интернет-соединения, токенов авторизации и не зависит от сторонней инфраструктуры.

## 10. Ограничения

В текущей версии решения имеются следующие ограничения:
1. **Объем базы знаний**: бот отвечает только на вопросы, покрытые базой `faq.txt` (5 основных тем репетиции). Вопросы за рамками этой базы классифицируются как неизвестные.
2. **Алгоритмический стемминг**: используется эвристическое усечение типичных русских окончаний без полноценного лексико-грамматического словаря (супплетивизм и редкие чередования корней не поддерживаются).
3. **Интерфейс**: решение выполнено в виде консольного CLI-приложения; веб-интерфейс и интеграция с Telegram/Discord в рамках текущей версии отсутствуют.
4. **Stateless-диалог**: бот обрабатывает каждый вопрос изолированно и не хранит контекст предыдущих реплик многошаговой беседы.
